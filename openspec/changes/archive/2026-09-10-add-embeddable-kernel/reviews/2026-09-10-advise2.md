## Blind take (written before delta, design.md, tasks.md)

Sources: proposal Why/What, `openspec/specs/living-specs/spec.md`,
`docs/architecture.md` at HEAD, `conduit/src/api.rs`, `conduit/src/error.rs`,
`RoomEventSender` + `Room::create` in `conduit/src/room/mod.rs`, `AuthState`
in `conduit-server/src/api/client/mod.rs`, `rooms.rs:100`,
`federation/server.rs:312`, all three `Cargo.toml`, and two `cargo tree`
runs (default and `--features iroh`). Delta spec NOT read for this take.

1. Pin the direction, not the graph. `Room::create` takes
   `&dyn RoomEventSender` and the host implements it (`main.rs:80`,
   `event_pipeline.rs:46`). The kernel asks the host to persist. The ADR
   must say kernel owns build-sign-auth-persist; host supplies `Storage`,
   keys, server name; today's inversion is debt owned by `add-library-ops`.
2. Pin the error contract. `conduit::Error` is six variants with
   `Storage(String)` as the catch-all. Matrix `errcode` is Matrix
   semantics; it belongs on the kernel error, host maps errcode→status.
3. Pin HTTP-type wording as API, not graph. Verified again: default
   `cargo tree -p conduit` has no `axum`/`http`/`reqwest`; `--features iroh`
   pulls `http`, `hyper`, `reqwest`, `tower-http`. So: no HTTP types in the
   public API; `axum` never in the tree under any feature; `http`/`reqwest`
   transitive behind `iroh` only. CI test = `axum` absent.
4. Pin what the kernel `Homeserver` owns. `AuthState` is the real
   homeserver today: storage, name, key, txn cache, events_tx, typing,
   presence, minter, identikey verifier. Table it: kernel vs host.
   Licensing edge belongs here too: workspace `Cargo.toml` says
   identikey-core (AGPL) must never be a dependency and "the host speaks
   OIDC to it" — so OIDC is host-owned by license, not just by taste.
5. Pin v11 in the kernel, both paths. `Room::create` accepts any
   `room_version: &str` and writes it; `rooms.rs:100` defaults but never
   rejects; `server.rs:312` reads whatever the create event says. Neither
   the create nor the inbound path rejects a non-11 version anywhere.
6. Refuse a feature flag that compiles `axum` into `conduit`.
7. Refuse "typed" satisfied by `serde_json::Value` envelopes. Event
   *content* as `Value` is fine (opaque by spec); op request/response
   types are not.
8. Pin runtime honesty: tokio is used in `room`, `auth`, `identity`,
   `storage`; `Storage` is 216 `async fn` behind `async-trait`. Embeddable
   = tokio-hosted.
9. Tradeoff to accept: an embedder wanting Postgres links axum until
   `conduit-6jr`. Fine. Escape hatch is the third crate, not a feature.
10. Acceptance is doc truth. `docs/architecture.md` at HEAD still says
    `conduit::auth *(planned)*`, "SQLite or RocksDB", and
    `conduit/src/api.rs` is titled "HTTP API surfaces". The amendment must
    describe the target and name HEAD debt so a stranger does not read it
    as a description of HEAD.

## Comparison (after delta, design.md, tasks.md)

Verdict: accept. S1–S3 from the send-back are answered in the delta
text, not only in design.md, which is what blocked before. One task box
added below; the rest are notes for the actor and folder.

Answered against the take:

- #1 direction: delta requirement "Kernel owns persist; host supplies
  I/O" + Decision 4. Verified the debt claim: `build_sign_and_persist`
  returns `Result<String, (StatusCode, Json<MatrixError>)>`
  (`event_pipeline.rs:94`), so "HTTP-typed persist" is literally true.
- #3 HTTP wording: delta now matches the API form and the `cargo tree`
  facts I re-ran. Task 3 tests the right thing (`axum` absent, both
  feature sets). S1 closed.
- #4 Homeserver split: Decision 6 table is the right shape. Steelman:
  it lives in the ADR, not the delta, which is correct because the
  table is ownership guidance, not a testable SHALL.
- #5 v11: delta covers create and inbound, kernel-side, typed error;
  Task 4 matches. Seam exists at HEAD: the host inbound pipeline
  already calls `conduit::auth::check_auth` (`federation/pipeline.rs:23`),
  so the check can land in the kernel now without waiting for
  `add-library-ops`.
- #6 #7 #9: refused/accepted exactly as the take asked. Delta names
  `(u16, Value)` stand-ins as forbidden and `conduit-6jr` as the escape.
- #8 tokio-hosted: requirement + doc scenario. Good.
- #10 doc truth: Task 1 enumerates every claim the doc must carry.
- S2 ("Host is replaceable" promise scenario) is gone; replaced by the
  crate-graph scenario under "Two crates", which is true at HEAD.

Steelman on the one place I hesitated: the "Kernel owns persist"
requirement is a target with HEAD named as debt inside the SHALL. That
looks like the S2 pattern, but it differs in the way that matters: its
scenario tests the doc, which is true at fold, and the requirement
text itself says HEAD inverts it. An ownership ADR whose SHALL names
its own debt is honest, not fiction. Accepting it.

### Box added to tasks.md (owed by this change)

**Errcode on `conduit::Error` has a delta requirement and scenario but
no task.** At HEAD the kernel has no `errcode` anywhere
(`grep errcode conduit/src` is empty) and `Error` is six variants. If
this folds as written, "Specs are truth" is violated on day one. The
fix is small and already implied: Task 4's "typed kernel error" for
v11 needs somewhere to live, and `M_UNSUPPORTED_ROOM_VERSION` is the
first errcode. One box: add an `errcode()` accessor (or variant
payload) on `conduit::Error` carrying at least `M_FORBIDDEN`,
`M_NOT_FOUND`, `M_UNSUPPORTED_ROOM_VERSION`; host maps it. The folder
should not fold the errcode requirement until this box is checked.

### Notes (non-blocking)

- Errcode scenario cites `may_read_room`, which returns `bool`
  (`auth.rs:778`), so it cannot name `M_FORBIDDEN`. Point the scenario
  at `require_read_access` (`auth.rs:905`) or at the v11 reject.
- v11 inbound scenario says "the kernel ingest path"; at HEAD the ingest
  path is host-side and calls kernel `check_auth`. Phrase it as "WHEN
  kernel auth runs on the PDU" so it is true before `add-library-ops`.
- Decision 6 table omits the identikey challenge verifier, which is on
  `AuthState` today and whose crate is already a kernel dep
  (`identity.rs`). It belongs in the kernel column. And say *why* OIDC
  is host-only: workspace `Cargo.toml` forbids identikey-core (AGPL) as
  a dependency; the license line is the boundary, not taste.
- Task 1 should also retire "SQLite or RocksDB" and the
  `conduit::auth *(planned)*` row in `docs/architecture.md`, and retitle
  `conduit/src/api.rs` away from "HTTP API surfaces". Small, but a
  stranger reading either would conclude the opposite of this ADR.
- Fold note: keep the sentence "This requirement is the target; HEAD
  still inverts it" verbatim in the living spec. `add-library-ops` owes
  a MODIFIED block that deletes it.
- Task 2 (fold) is still process-owed, as the prior review said.
  Harmless.
