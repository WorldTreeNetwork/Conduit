## Blind take (written before design.md / tasks.md)

Sources: proposal Why, living-specs, delta spec, `conduit/src/api.rs`,
`conduit-server/src/api/client/event_pipeline.rs`, `docs/architecture.md`,
both `Cargo.toml`, `AuthState` in `conduit-server/src/api/client/mod.rs`,
`RoomEventSender` in `conduit/src/room/mod.rs`, `conduit/src/error.rs`,
and one `cargo tree` run. Disclosure: I read the delta spec before
writing this take; the packet said to read it after.

1. Pin the dependency direction, not just the crate graph. Today the
   kernel trait `RoomEventSender` is implemented by the host and the
   kernel's `room` module calls *up* into `conduit-server` to persist.
   The ADR must say the kernel owns build-sign-auth-persist and the host
   only supplies `Storage` + keys + name. Otherwise "two crates" is true
   and the inversion survives.
2. Pin the error contract. Matrix `errcode` (M_FORBIDDEN, M_NOT_FOUND,
   M_UNKNOWN_TOKEN, M_LIMIT_EXCEEDED …) is Matrix semantics, not HTTP.
   It belongs on `conduit::Error`; the host maps errcode → status. The
   present six-variant enum plus `Storage(String)` as a catch-all is how
   HTTP-shaped errors will leak back in disguised as strings.
3. The delta's crate-graph scenario is already false under a kernel
   feature: `cargo tree -p conduit --features iroh` pulls `http`,
   `hyper`, `reqwest` (iroh-relay). The proposal says "as API", the delta
   says "not in the crate graph". Choose one: I'd pin "no HTTP types in
   `conduit`'s public API; `axum` never in the graph; `http`/`reqwest`
   tolerated transitively behind `iroh` only." And add a test that fails
   if `axum` appears in `cargo tree -p conduit`.
4. Name what the kernel's `Homeserver` is. `AuthState` (storage, key,
   name, txn cache, events_tx, typing, presence, minter) is the real
   homeserver object today and lives in the host. The ADR should say
   which of those move (storage, key, name, stream broadcast, txn cache,
   typing, presence, minter = kernel) and which stay (OIDC, media disk,
   rate limit, push worker = host).
5. v11 freeze must be enforced in the kernel, not the host. Today
   `rooms.rs:100` defaults to "11" and rejects nothing; federation
   `server.rs:312` reads whatever the create event says. If the check is
   only in an axum handler the in-process client bypasses it.
6. Refuse: any feature flag that compiles `axum` into `conduit`; a third
   Postgres crate in this change (both already out of scope — good).
7. Refuse: "no HTTP types" satisfied by returning `(u16, Value)` or
   `serde_json::Value` bodies from kernel ops. Typed means typed.
8. Tokio is a kernel dependency and `Storage` is 216 `async fn`s behind
   `async-trait`. "Embeddable" therefore means embeddable in a tokio
   host, not runtime-agnostic. Say so; don't let a later node claim more.
9. Tradeoff to accept: two crates means an embedder who wants durable
   storage links axum. That's the price of not splitting Postgres now.
   Fine, but the ADR should say the escape hatch is `conduit-6jr`, not
   a feature on `conduit`.
10. This node owes an ADR and a doc amendment, nothing runnable. Its
    acceptance should be: living spec text + `docs/architecture.md`
    match reality *as a target*, with the current inversion named as
    debt owned by `add-library-ops`, so a stranger doesn't read the doc
    as a description of HEAD.

## Comparison (after design.md / tasks.md)

  `conduit-6jr` (take #6, #9). Decision 1 is right and says why.
- In-process `Client` on `conduit`, not an HTTP SDK (take #4, partly).
- v11 rejected with a typed library error, host maps it (take #5, create
  path). Task 4 puts the check in the kernel. Good.
- Scope honesty: this node writes the ADR and does not move
  `build_sign_and_persist` (take #10). Steelmanned: an ownership ADR
  that names the boundary and leaves the move to `add-library-ops` is
  the correct size.

Not answered. The first three block fold because they are in the delta
text or are the question the change exists to answer.

### S1 — Delta "Kernel has no HTTP types" is false at HEAD under a kernel feature

`cargo tree -p conduit --features iroh` pulls `http`, `hyper`, and
`reqwest` through iroh-relay. The scenario says "without enabling host
features"; `iroh` is a `conduit` feature, not a host feature, so the
requirement as written fails today and the Task 3 "compile-time deny"
would fail with it. Proposal says "as API"; delta says "in the crate
graph". Pick the API wording:

> `conduit` SHALL NOT expose `axum`, `http`, or `reqwest` types in its
> public API. `axum` SHALL NOT appear in `cargo tree -p conduit` under
> any feature. `http`/`reqwest` MAY appear transitively behind the
> `iroh` feature only.

Then Task 3's check is `axum` absent from the tree, tested in CI.

### S2 — Delta "Host is replaceable" scenario is a promise, not a truth

The scenario ends "once `add-library-ops` and `add-in-process-client`
have landed". living-specs says a folded spec claims to be true of the
current system. Reword to what is true at HEAD (a consumer of `conduit`
alone can build `MemoryStorage`, keys, and call `check_auth` /
`state_res` without a port) and leave the in-process embed scenario for
`add-in-process-client`'s delta.

### S3 — The ADR does not state the dependency direction

`RoomEventSender` is a kernel trait the host implements; `conduit::room`
calls up into `conduit-server` to persist. Design.md names the crates
but not who owns build-sign-auth-persist. One sentence in the ADR and
the delta: kernel owns the pipeline; host supplies `Storage`, keys,
server name; the current host-side impl of `RoomEventSender` is debt
owned by `add-library-ops`. Without this, `docs/architecture.md` is
fiction again the day it lands.

### Notes (boxes added to tasks.md, non-blocking)

- Error contract (take #2): Matrix `errcode` belongs on `conduit::Error`,
  host maps errcode → status. Say so in the ADR so `add-library-ops`
  doesn't grow a parallel `MatrixError`.
- v11 inbound (take #5): delta says "create and inbound events"; Task 4
  covers create only. Either add the inbound check to Task 4 or narrow
  the delta to create for this change.
- `Homeserver` vs host ownership (take #4): a short table in the ADR of
  what moves from `AuthState` into the kernel (storage, key, name,
  stream broadcast, txn cache, typing, presence, minter) and what stays
  (OIDC, media disk, rate limit, push worker).
- Runtime (take #8): kernel depends on tokio and `Storage` is
  `async-trait`; "embeddable" means tokio-hosted. One line.
- Task 2 (fold) is process-owed, not change-owed; harmless as a box but
  the folder does it, not the author.
