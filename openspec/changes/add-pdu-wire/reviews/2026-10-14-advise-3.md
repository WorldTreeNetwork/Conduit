## Notes for act (non-blocking, ranked)

1. **Write the TEXT sinks with lossless JSON text, not Matrix canonical JSON.** This is the one note `act` must not skip.
   - **The trap.** The delta says `transactions.request`, `transactions.result` and `fed_outbound_queue.payload` "SHALL hold canonical JSON as `TEXT`". `conduit::canonical_json::to_canonical_string` refuses floats and integers outside ±(2^53-1) (`canonical_json.rs:66-90`).
   - **Why the encoder fails.** `Replay::body` stores the whole `/send` body before any PDU is decoded (`replay.rs:107`). That body can legitimately contain:
     - a non-canonical PDU, which must be dropped per PDU (scenario "Non-canonical values are dropped");
     - an EDU, or a client to-device body, carrying a float.

     The canonical encoder would turn each of those into an error on the whole transaction (a 5xx, retried until it lands). Today JSONB accepts floats, so this would be a regression: the B1 wedge, moved into the encoder.
   - **The fix.** Use `serde_json::to_string` / `from_str`. It escapes U+0000 as `\u0000` and keeps floats. The delta's own SHALLs already forbid the wrong choice ("SHALL NOT cause a 5xx"; "other PDUs and EDUs SHALL still be processed"). Read "canonical" there as "JSON text".
   - **The tests.** Add to the U+0000 `/send` test a PDU holding `1.5` (dropped, no entry, 200) and an EDU holding a float (processed). Add one client to-device `PUT` whose content holds a float.
2. **The 65536-byte measure is not what Synapse measures.**
   - **What Synapse counts.** Synapse's `_check_size_limits` encodes `event.get_pdu_json()` (`event_auth.py:473`). After `event_from_pdu_json`, that object still holds `unsigned`, with received `age` rewritten to `unsigned.age_ts = received_time - age` (`federation_base.py:343-360`; `rust/src/events/mod.rs:287-312` only converts it back when `time_now` is given). So Synapse counts about 13–35 more bytes than design step 3, which excludes `age` and `age_ts`.
   - **The divergence.** A PDU in that sliver below 65536 is accepted by Conduit and treated as `unpersistable` by Synapse. It is adversary-constructible, but needs a near-64 KiB event, and Synapse's own measure depends on receive time, so exact parity is impossible.
   - **The fix.** Do either:
     - (a) count the allow-listed `unsigned` as received, `age` included, which narrows the window to a few bytes; or
     - (b) keep the rule and add this to the recorded divergences next to the content-hash one.

     In both cases, remove the sentence "This is what Synapse measures".
   - **Authored PDUs.** Separately, Conduit-authored PDUs that approach 65536 bytes will be dropped by Synapse for the same reason. When a client-side `M_TOO_LARGE` cap is added, leave a margin of at least 64 bytes, or file a bead.
3. **The sink table's "only SQL readers" claim is stale.** The design says the only `events.content` SQL reader is `content->>'membership' = 'join'`. Since `150d9ca`, `search_user_directory` also reads `displayname`, `avatar_url`, `join_rule` and `history_visibility` from the projection (`storage_pg.rs:3338-3358`).
   - The two equality predicates stay correct, because a NUL-bearing value is neither `public` nor `world_readable`.
   - A member `displayname` containing U+0000 will appear in directory results as U+FFFD. That is acceptable.
   - Update the table row so that the next sink audit starts from the truth.
4. **EDU class-22 drop.** Run each EDU persist in its own statement or under a `SAVEPOINT`. A failed statement inside a shared PG transaction aborts every later statement ("current transaction is aborted"), and that would surface as a different SQLSTATE class and a 500. Make sure `map_sqlx` keeps the SQLSTATE so that the class-22 test can see it.
5. **Small delta–design gaps.** The design is the stricter of the two in each case. Implement the design and tighten the delta at fold.
   - The delta's `send_join` response `event` omits "`hashes` unchanged, and the resident signature verifies".
   - The delta's `/state` omits "state event, `room_id == room`".
   - For `get_missing_events`, "requested seed" means the `prev_events` of `latest_events`. That event is in hand, not necessarily persisted.
   - Specify that a duplicate `(type, state_key)` in `send_join` `state` fails the whole join, rather than dropping one entry.
6. **No callers yet.** `client.state`, `state_ids`, `backfill`, `get_missing_events` and `send_join` have no callers today (`federation/client.rs:541-653`). The only persisted fetch remains `pipeline.rs::fetch_missing_auth_events`. The B3 tests therefore have to drive `admit_fetched` directly with canned responses. A wiring test cannot cover them.
7. **Row-decoder line numbers.** The nine `Event { .. }` literal sites are now at `storage_pg.rs` 228, 295, 829, 865, 895, 1036, 1098, 1145 and 1211 (each one line later than the design says). The count is unchanged.
